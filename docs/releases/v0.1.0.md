# DoneWitness v0.1.0

## What DoneWitness is

DoneWitness is a deterministic acceptance verifier for AI-written web software. It runs a frozen,
human-reviewed plan against an actual locally runnable application and produces evidence-backed
`PASS`, `FAIL`, or `UNKNOWN` receipts without requiring a judge model.

## Why v0.1 exists

v0.1 establishes a small deterministic trust layer: reviewers freeze explicit acceptance criteria,
run observable browser procedures, and receive traceable `PASS`, `FAIL`, or `UNKNOWN` results.

## Highlights

- Versioned Plan v1/v2 input and deterministic Playwright verification.
- Bounded evidence manifest, receipts v1–v4, and `donewitness inspect`.
- Read-only Git provenance and optional requested-revision disposable worktrees.
- Optional Linux-qualified Docker isolation baseline.
- Stable exit codes and machine-output schema v1 for CI.

## Installation

```console
python -m pip install donewitness==0.1.0
python -m playwright install chromium
donewitness --version
```

The distribution is `donewitness`, the Python import package is `donewitness`,
and the console command is `donewitness`.

## Minimal example

From a checkout containing the maintained examples:

```console
donewitness verify --plan examples/greeting.plan.json --base-url http://127.0.0.1:8765 --run-dir .donewitness/v0.1-demo --app-command python examples/greeting_app.py
donewitness inspect --run-dir .donewitness/v0.1-demo
```

## CI usage

Use `--output-format json`, retain the finalized run directory only under an explicit privacy
policy, and treat exits 1, 2, and 3 as non-passing outcomes. Machine output remains schema v1.

## Supported environments

Python 3.12–3.14 is release-qualified. Direct and revision verification are qualified on Linux and
Windows. Docker isolation is qualified only on Linux. macOS is not release-qualified for v0.1.

## Security and isolation limitations

Direct mode runs with caller permissions. Docker reduces exposure but is not hostile-code or VM-
grade isolation. Docker, the host/VM kernel, local Git configuration, and host-side Chromium remain
trusted. Evidence may contain sensitive application content.

## Known limitations

v0.1 supports local web applications and explicit deterministic browser procedures. It does not
generate acceptance criteria, browse autonomously, provide a hosted service, sign artifacts, or
offer cryptographic attestation.

## Artifact and integrity model

The release provides one pure-Python wheel, one sdist, and ordinary SHA-256 download checksums.
DoneWitness run manifests and receipts use unkeyed hashes as integrity indicators, not signatures,
authentication, or attestation.

## Schema compatibility

Receipt schemas v1–v4 are supported as documented, and new runs emit v4. Consumers should branch on
schema versions and ignore unknown future machine-summary fields. Undocumented Python internals may
change before 1.0.
